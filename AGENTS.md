## Code Review Rules

- Write like an experienced colleague: direct, professional, and natural.
- Keep each comment to one short paragraph. State the issue, when it happens, and its practical impact. Suggest a fix when useful.
- Avoid generic praise, emojis, filler, and phrases such as “It's worth noting,” “To ensure robustness,” or “Consider leveraging.”
- Be specific about the code. Avoid lectures and repeating what the change already makes clear.
- Match certainty to evidence. Explain any uncertainty without unnecessary hedging.
